git-dispatch

Stacked PRs without the stack.

Code a feature on one branch, tag each commit with the PR it belongs to, and git-dispatch builds one independent branch per PR off base. A PR can hold any number of commits. No force-push. No restack. No cascade.

The problem

You code the whole feature on one branch, then need focused PRs for review. Stacked PR tools such as Graphite, ghstack and spr put each branch on top of the one before. When a parent PR merges, every child has to be rebased and force-pushed, and review context is lost.

ghstack and spr also map one commit to one PR. With git-dispatch, a PR is as many commits as it needs.

How it works

Don't stack. Each PR branch starts from base and carries only its own commits, so when one PR merges, the others are unaffected.

  1. Tag. Commit with git dispatch commit and a --target number. The number is stored in a Dispatch-Target-Id trailer and decides which PR the commit goes to.
  2. Project. git dispatch project builds one branch per PR off base, ready to push.
  3. Test together. CI needs the code combined? git dispatch combined makes a throwaway branch from the PRs you pick, without stacking them for good.

State lives in .dispatch/state.json, readable by people, scripts and AI agents through git dispatch status --json.

Install

Needs Git 2.x+ and Bash 3.2+ (macOS compatible).

git clone git@github.com:KakkoiDev/git-dispatch.git
cd git-dispatch
bash install.sh

install.sh adds a global git dispatch alias that runs the script from the clone.

Example: one feature, three PRs

# Start the feature branch and point it at master
git checkout -b feature/auth master
git dispatch init --base origin/master --target-pattern "feature/auth-{id}"
git dispatch state init --from-config

# Commit as usual, naming the PR each commit belongs to
git dispatch commit "Add user model"        --target 1
git dispatch commit "Add auth middleware"   --target 2
git dispatch commit "Add login endpoint"    --target 2
git dispatch commit "Add validation"        --target 3

# Build one branch per PR off master
git dispatch project
# feature/auth-1  (1 commit)
# feature/auth-2  (2 commits)
# feature/auth-3  (1 commit)

# Push each branch, then open the PRs
git dispatch push 1
git dispatch push 2
git dispatch push 3

Later, as the PRs move through review:

# Review commits pushed to a PR branch? Bring them back
git dispatch absorb

# Test PR 1 and PR 3 together on a throwaway branch
git dispatch combined --include 1,3
git dispatch combined --dissolve

# master moved on? Catch up, drop merged PRs, rebuild
git dispatch update-base
git dispatch clean
git dispatch project

Coming from the old commands? apply, sync, checkout and checkin still work and print a deprecation warning in a terminal. The migration guide maps each one to its new name.
